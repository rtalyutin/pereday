## Сценарии прототипа

1. Автор выбирает одну из трёх основ, подтверждает, получает сохранённые 1/16 и передаёт ссылку. Выбора следующей детали для собственного узла нет.
2. Получатель видит исходные 1/16, примеряет одну из трёх деталей без изменения счётчика, подтверждает и получает 2/16.
3. Получатель B имеет отдельный вход. В дереве демонстрируются независимые дети одной исходной базы. Переключателя личности в продукте нет.
4. Повторное открытие ведёт к первому результату, без замены выбора.
5. Каркас источника 15/16 → выбор таблички → сохранение → каркас 16/16. Прямой просмотр финала не требует сессии.
6. Отдельная демонстрация потери ответа: выбор → подтверждение → неизвестный исход → проверка той же попытки → сохранённый результат.
7. Мои работы → свой результат → дерево → раскрытие и следующая страница той же группы.
8. CTA присутствует в игре и финале. Пока адрес не задан, он ведёт к явно обозначенной заглушке конфигурации; внешний контакт не подменён вымыслом.

Переходы по таймеру 1 s **моделируют** ответ сервера. Они не выполняют API-запрос и не задают допустимое время ответа продукта. Copy/Web Share здесь также являются демонстрацией состояний. Реальный Figma Player не был пройден вручную.

## Адаптивность и доступность

- Контрольные ширины: 320, 390, 1280 px. До 960 px одна колонка, от 960 px две; максимальная внутренняя ширина 1200 px. Внешний отступ 20 px на мобильном и 40 px на широком.
- Все три варианта находятся в вертикальном потоке. Длинные названия переносятся без ellipsis. На 200% текста карточка использует вертикальное расположение.
- Сцена вписывается целиком. При изменении размера масштабируется общий квадрат; отдельные детали не подгоняются.
- Порядок чтения: шапка → заголовок → сцена одним описанием → сохранённый прогресс → группа вариантов → подтверждение → CTA.
- Группа реализуется как radiogroup: Tab входит в группу, стрелки перемещают выбор, Space выбирает вариант. Подтверждение записи — отдельное действие.
- Статусы объявляются через aria-live polite. Изображения слоёв декоративные; доступное описание относится к целому существу.
- Панель передачи в реализации получает семантику диалога, удерживает фокус, закрывается по Escape и возвращает фокус на вызвавшую кнопку. На низком экране прокручивается по высоте; URL доступен для ручного выделения.
- Смена сцены и подтверждённого результата мгновенная. Hover 150 ms; reduced motion 0 ms. Нет звука, тряски и ожидания анимации.
- Слои изображения: ноги 10, база 20, глаза 40, рот 50. Интерфейс выше сцены; модальная панель выше интерфейса. Декоративные слои не перехватывают события.

Проверка указанных критериев в макете не является заявлением о полном соответствии WCAG готового приложения.

Схема будущих зон помечена как предложение, не как manifest: нимб сверху, артефакт слева, спутник справа, след под ногами, финальная табличка ниже следа. Численные размещения и совместимость поздних деталей не утверждены.

## Состояние frontend и расхождения

В архиве сохранён frontend v0.2: React + TypeScript + Vite, явные demo и REST adapters. Ранее прошли 12 тестов и production build; подробности — `QA.md`. В этой итерации код приложения не переписывался. Макет v0.3 не выдан за уже синхронизированный frontend.

При переносе дизайна в код нужно применить новый набор компонентов/отступов, расширенные состояния панелей, вертикальную карточку крупного текста и адаптивный порог 960 px. Текущий CSS v0.2 отличается декоративными тенями, некоторыми размерами текста и прежними breakpoint. `design-tokens.css` — точный материал передачи, он не подключён вместо CSS приложения автоматически.
