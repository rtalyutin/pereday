# Передай · Альбом дичи

Frontend v0.2 на React + TypeScript + Vite, backend v0.1 на Node.js + PostgreSQL и комплект дизайна v0.3 в Figma. Светлый «Альбом дичи», 12 исходных PNG, локальная демонстрация, реальный REST API и серверное дерево. Это проверяемая промежуточная версия, а не готовый публичный продукт.

[Макет и индекс экранов в Figma](https://www.figma.com/design/928uR3KiThQ0aUC9AZq8C8?node-id=58-1561) · [Спецификация макета v0.3](docs/Design-Handoff-v0.3.md) · [Все фреймы](docs/screen-index.md) · [Превью](docs/previews/)

## Запуск

Требуется Node.js 22.22.2+ (ветка 22) или 24.15.0+ (ветка 24). Проверки выполнены на Node.js 24.19.0.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. `index.html` нельзя запускать двойным щелчком: нужен HTTP-сервер с поддержкой SPA-маршрутов `/c/*`, `/s/*`, `/mine`.

```sh
npm test
npm run build
npm run preview
```

Команда `npm run build` создаёт `dist/`. Зависимости и результаты сборки не хранятся в репозитории.

## Сценарий демо

1. Выберите одну из трёх баз. Счётчик остаётся 0/16, пока не нажата кнопка сохранения.
2. Подтвердите вклад. Сохраняется версия 1/16, появляется получение ссылки.
3. Откройте ссылку в другом браузерном профиле. Получатель может примерить три варианта глаз и подтвердить один.
4. Сохраняется отдельная версия 2/16. Исходник остаётся неизменным. Другой получатель может создать другую ветку.
5. Повторное открытие той же ссылки получателем ведёт к его существующему результату. Автор не дополняет собственную версию.

В демо ссылки несут открытый снимок существа; они не подписаны и не являются серверной авторизацией. Данные, история операций и дерево хранятся локально. Между браузерами передаётся снимок, но общего дерева и общего сервера нет. В интерфейсе нет переключателя личности.

## Режим настоящего API

Backend реализован в `server/`: миграция PostgreSQL, HTTP-обработчики, сессии, транзакционные команды, каталог, общее дерево и события. Запуск PostgreSQL, миграция, разделение ролей, демо seed и прокси описаны в [инструкции](docs/Backend-Runbook.md); API — в [OpenAPI](server/openapi.json). Для локального live-режима установите переменные из `.env.example`, запустите `npm run server:dev`, затем `VITE_API_MODE=live npm run dev`. Frontend обращается к `/api/v1` через Vite-прокси. При сетевой ошибке REST-режим не переключается на демо.

Для **единой production-сборки** запустите `VITE_CAMPAIGN_SLUG=peredai npm run build:production`, затем с настройками PostgreSQL и HTTP из `.env.example` — `npm run start:production`. Один процесс Node.js отдаёт `dist/` и `/api/v1/*` на порту `PORT` либо `PEREDAI_PORT`; Vite здесь не работает. До открытия порта сервер проверяет live-режим сборки, slug, наличие файлов и кампании в БД. Подробный порядок и ограничения — в [инструкции](docs/Backend-Runbook.md). Код единой поставки подготовлен локально, рабочий HTTPS-адрес не развёрнут.

`VITE_CAMPAIGN_SLUG` задаёт кампанию. В live-режиме бренд, оффер и CTA приходят с сервера. `VITE_CTA_TARGET` применяется только к демо; по умолчанию контакт не выдуман и не активен.

CSRF живёт в памяти; cookie должен выставлять backend. Бизнес-команды используют `Idempotency-Key`; точные тело, ключ, цель и browser profile ID сохраняются до отправки. После неопределённого ответа проверка повторяет ту же команду. При потере профиля повтор заблокирован. Для согласования вкладок используются Web Locks. Без Web Locks запись отключена.

## Что реализовано

- Выбор базы, получение по ссылке, примерка, сохранение, неопределённый ответ и восстановление, сохранённый результат и передача.
- Финал 16/16, список «Моя дичь», раскрываемое дерево с пагинацией, недоступная ссылка и отсутствие графики.
- Один вклад на полученный снимок, независимые ветви, неизменяемый префикс, предел 16. Правило D01 отображается как нерешённое.
- SVG-компоновка по версионному каталогу: исходный размер, anchor, перенос, поворот, scale, z-order. Есть SVG alpha-mask для clip-to-base; текущие детали её не используют.
- Нативные radio controls, focus-visible, статус примерки, ошибки загрузки с повтором, блокировка сохранения отсутствующей графики, reduced motion.
- Отдельная подготовка ссылки и открытие системного меню по новому нажатию. Отмена меню не считается передачей. Есть копирование и ручное выделение URL.

## Что остаётся

- **36 иллюстраций шагов 5–16.** Общее число шагов не сокращено. В доменной модели проверена цепочка до 16, но интерфейс не разрешает сохранить невидимую деталь.
- Реальная кампания и контакт, production-каталог, политика хранения клиентских операций и конкурентная приёмка на серверном PostgreSQL.
- Решение D01 о повторном участии предка через потомка.
- Браузерная проверка на 320/390/768/1440 px, реальные Web Share/Clipboard, cookie, offline, долгие таймауты и несколько вкладок. DOM-тест не заменяет эти проверки.
- Синхронизация frontend v0.2 с полным комплектом макета v0.3.
